# inv-recipes
Recipes subsystem inventoried. Inventory JSON has 51 entries: all 45 assigned tracked files appear exactly once, plus 6 recipe-owned files outside my globs flagged for other inventories. Evidence comes from file reads, a scratch clone of awesome-blog (npm ci, build, recipes:check, test:recipes: 55/55 pass), a scratch clone of jsolly-website (clean build; Biome and Knip run over a copy of the recipe tree), HEAD checks against production, and the Service Worker spec text.

Pipeline: recipes.json (21 recipes: 15 meals + 6 smoothies) feeds sync-recipe-article.mjs, which rewrites keyed regions of the 157 KB post markdown. It also feeds sync-assistant-data.mjs, which writes public/data/recipe-library.json (389,731 B) and recipe-library.md (159,124 B). The generated post markdown is never rendered on the live site: the post route renders RecipeExperience instead, and the built HTML has 0 matches for the editorial prose. So the post, the article generator and its 5 tests can be dropped with no live-content loss. The editorial prose (food-safety temperatures, preheat and capacity notes, nutrition method, leftovers) lives only in that markdown, which is decision D2. No local repo, dotagents skill or memory references the assistant data URLs. External consumers such as Grok Bot cannot be checked locally.

Tests: 55 pass in test:recipes. That is 36 unit tests, 5 article-generator, 1 migration-rewrites and 13 Playwright PWA tests. 11 of the 13 PWA tests port; 2 legacy-worker tests are dropped.

PWA: production serves two worker URLs: /recipe-service-worker.js (scope /, since #694 on 2026-10-03 22:40) and the legacy /post/15-minute-.../service-worker.js (scope = the post path, since #689). A plain 301 would not reach installed users: the worker answers recipe navigations from cache, and the spec's script-update fetch uses redirect mode "error". Both worker URLs therefore need a 200 tombstone and must stay out of every redirect rule. The concrete tombstone code, the new /recipes/ scope, manifest and layout, and the content-freeze procedure are in the notes file.

Cutover-ordering catch: jsolly-website main deploys to production on merge, so porting commits must not reach main before John approves the deploy step.

Not built: a full merged build (astro build + process-html + built-csp test) was never run. I started a scratch spike, but the build step was blocked by the auto-mode classifier, so I stopped.
