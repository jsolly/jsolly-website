# DST (jsolly-website) conflict notes

Evidence base: DST main 5694e76, SRC (awesome-blog) origin/main bf1f7ff1. Everything below was read from tracked files or reproduced in scratch clones under `clones/dst-conflicts/` (jsolly-website = pristine build, jsolly-overlay = hand-merged DST + blog code, srcdump = `git archive` of SRC). SRC and DST checkouts were not touched (both `git status` clean at the end). Full structured list: `conflicts-dst.json` (27 entries).

## Ranked findings (what changes the plan)

1. **Svelte hydration is already broken by `process-html.mjs`** (pre-existing). `removeComments` deletes Svelte's `<!--[-->` markers and `collapseWhitespace` deletes whitespace text nodes, so each island re-renders instead of hydrating (nav island: 2 elements removed on load with process-html, 0 without). Comment preservation alone still gives `hydration_mismatch`; `conservativeCollapse: true` + `ignoreCustomComments: [/^\[/u, /^\]/u, /^$/u]` fixed it (0 removals, no warning, +123 B on index.html) and was verified against `built-csp.test.mjs` (pass, 145 pages), style hashes (0 mismatches) and byte-identical pre/script/style content. It can ship as its own PR ahead of the merge; land it before any blog island ships.
2. **Middleware would break feeds, assistant data and every Markdown alternate.** Probe results: `/blog/rss/` + `Accept: application/rss+xml` gives 406; `/data/recipe-library.md` gives a Markdown 404 (the `.md` branch runs before static files); `/blog/<real-slug>/` + `Accept: text/markdown` gives 404 while `Layout.astro:38-40` would advertise a `.md` alternate on every page IF blog pages adopt that head (the blog's own `Base.astro` emits none). Live production already returns 406 for `/blog/x.avif` with `Accept: application/json`. There is no `config.matcher`, so it also runs for every asset. Recommended: discriminate by route existence (a build-time manifest of real pages), not by URL prefix, so an unknown `/blog/nonexistent/` with `Accept: text/markdown` keeps the 404 Markdown recovery body that `llms.txt` promises; exempt feeds/`/data/`/`/media/`/SW files and add a `config.matcher`.
3. **CSP intersection blocks real blog content.** With the vercel.json header (`img-src 'self' data:`) plus Astro's meta (`default-src 'self'`): all CloudFront images (the only external image host in 145 built pages; 627 references) and all 16 iframes (YouTube 13, nbviewer 2, diagrams.net 1) are blocked (reproduced in Chromium; 129 violations on 8 sampled pages, 105 broken images on `/all-posts/`). Moving the blog's directive list into `astro.config.ts` and widening/removing the header's `img-src` gives 0 violations, SW active. `built-csp.test.mjs` already passes for all 145 overlay pages (inline script hashes), but cannot see this class of failure. Recommended: single source of truth in Astro config, header keeps only `frame-ancestors`, `object-src`, `base-uri`, `upgrade-insecure-requests`; extend the test with a meta-and-header host-allowance check and `style-src-elem` hash check.
4. **Recipe PWA service worker has scope `/`.** On jsolly.com it would control the whole origin. Also: the manifest, route constants and legacy worker are hard-wired to `/post/15-minute-dump-and-go-instant-pot-recipes/`; the SW cache hash is computed in `astro:build:done` before `process-html` rewrites HTML (stale-version risk); DST's smoke runner blocks service workers so prod never exercises it. For users who already installed the PWA on blogthedata.com, the old worker serves the cached recipe page on navigation and its update fetch of `/recipe-service-worker.js` would hit a redirect (SW script updates refuse redirects), so they would never reach jsolly.com. The blogthedata.com side needs a non-redirecting self-unregistering worker at both old SW URLs. Related Vercel fact: `/.well-known` cannot be redirected or rewritten, so `blogthedata.com/.well-known/security.txt` stays a served file on the old domain's project.
5. **Redirect status codes:** `permanent: true` in vercel.json emits **308** (confirmed live on the apex redirect); John asked for 301, so each rule needs `statusCode: 301`. vercel.json limit is 2,048 redirects. The vercel.json host redirect runs before middleware (confirmed live), so a redirect-only blogthedata.com project is cleaner than attaching the domain to this project (unmatched blogthedata.com paths would otherwise serve jsolly content).
6. **Dependency/tooling hard stops:** `npm install` fails with `EOVERRIDE` (DST overrides `yaml >=2.8.3`; blog has `yaml` 2.9.1 as a direct dependency used at runtime by `src/lib/frontmatter.ts`); fix with `"yaml": "$yaml"`. Biome (`biome ci --error-on-warnings`) over blog-origin code only (deps installed, aws/, one-off migration tooling and public/data excluded) gives 1,071 errors + 106 warnings in 96 of 111 files (useLayeredStyles 428, useTopLevelRegex 134, noImportantStyles 99, useUnicodeRegex 94, useConsistentTestIt 70, ...); an earlier whole-tree figure of 1,362 included artifacts and is superseded. Biome 2.5.14 does not process Markdown at all (the `**/*.md` include is a no-op), so posts are not a Biome problem. markdownlint passes on the 106 posts only because `src/content/posts/.markdownlint.json` travels with them (otherwise 423 issues in 52 files). `knip` on the overlay: only the expected shadcn leftovers, unused turndown/svelte-check deps and the unlisted `yaml`. `astro check`/`svelte-check`: 2 real errors in `src/lib/html.ts:57-58`. 45 blog unit tests pass unchanged in DST's toolchain; `browse.test.mjs` needs re-pathing.
7. **CSS isolation works only if two layouts stay separate.** Per-layout CSS bundles do not leak in the overlay (about page loads only `Layout.*.css`; posts load `Base.*.css`). The blog's `global.css` is unlayered and would override DST's layered Tailwind on any shared page; DST biome requires layers. Tailwind 4 auto-source scanning grew `Layout.*.css` from 45,779 B to 57,836 B once blog files existed; use `source(none)` + explicit `@source`.
8. **`process-html` also creates duplicate heading ids** (27 pages vs 3 without it; the recipe article has `cooking-flow`, `ingredients`, `before-you-start` x15 each). It is otherwise safe for `<pre>`/script/style bytes (0 differences across 124 pre, 533 inline scripts, 169 styles; style CSP hashes all still valid).

## Answers to the specific questions

- **Markdown negotiation scope:** applies to every GET/HEAD path except `/_astro/`, `/favicons/`, `/images/`, `/scripts/` prefixes and the extension denylist; `.md` paths always. For paths not in `agent-pages.ts`: `Accept` resolving to HTML (including `*/*`/none) passes through to static; `text/markdown` or any `.md` gives a 404 Markdown body; an Accept matching neither HTML nor Markdown gives 406. No matcher. It would run on `/blog/*`, `/recipes/*` and on any attached host. HEAD is supported (empty body). Maintenance mode returns 503 Markdown for Markdown requests. Production smoke relies on it only for `/about/` (200, `text/markdown`, `Vary: Accept`, `# John Solly`). Blog Markdown variants are an option (posts are Markdown), best done as build-generated static siblings, not the in-code string table.
- **process-html:** slug = trim, replace `[\s.,?:]+` with `-`, strip trailing `-`, lowercase; keeps existing ids; no dedupe. Options: removeComments, preserveLineBreaks, collapseWhitespace only (no minifyJS/CSS, not conservative). Processes all `dist/**/*.html`. Trims leading indentation/trailing blank lines of inline script/style text but real output showed no drift.
- **vercel.json:** `trailingSlash: true`; `git.deploymentEnabled` main only; apex to www host redirect (308); one global header block. SRC's extra headers (feed Content-Type, release.json no-store, SW no-cache) must be re-pathed to `/blog/...`.
- **Pages that collide:** privacy (merge into DST's), 404/500 (keep DST), robots (static file vs `robots.txt.ts`; keep static and add the search Disallow), sitemap (integration only; add `filter` for `/blog/search/`, optional `serialize` for lastmod), favicon (DST wins), `release.json` (optional), security.txt/pgp-key (new for jsolly.com).
